# Контекст проекта

Обучение LoRA-адаптера поверх замороженной LLM: робот решает не только что
делать, но и **когда вмешиваться**, и дообучается на неявной реакции человека.
Это диссертационная работа, поэтому корректность метода важнее скорости.

Дизайн и научная постановка: `docs/superpowers/specs/2026-08-12-llm-agency-design.md`
Инструкция по запуску: `README.md`

## Инварианты, которые нельзя нарушать

1. **Базовые веса модели заморожены навсегда.** Обучается только LoRA-адаптер.
   Речевой контур — это та же база с ВЫКЛЮЧЕННЫМ адаптером. На этом держится
   защита от катастрофического забывания; полное дообучение ломает работу.

2. **Валидность команд обеспечивает грамматика декодера, а не обучение.**
   Схема `RobotDecision` компилируется в грамматику. Не ослабляйте инварианты
   схемы: `WAIT` и `OBSERVE` не могут нести `speech` или `motion`, иначе модель
   выучит вырожденную стратегию «формально промолчал, но реплику приложил».

3. **К схеме решений приводятся только корпуса проактивности.**
   Function-calling и replay остаются в родном диалоговом формате: их задача —
   сохранить уже имеющиеся навыки, и перегонка в `RobotDecision` их уничтожит.

4. **Баланс ACT/WAIT держится около 50/50** прореживанием преобладающего
   класса. Никогда не размножайте редкий класс — это переобучение на нём.
   Без выравнивания модель приходит к стратегии «молчать всегда»: высокая
   формальная точность при полной бесполезности.

5. **Эталонная метка в данных ProactiveAgent — поле `category`, а не
   `help_needed`.** Проверено на данных: среди записей с `help_needed=True`
   есть 244 штуки категории False-Alarm. `help_needed` — суждение агента,
   `category` — сведённая человеческая разметка.

6. **Проактивный корпус мал (~1000 примеров после выравнивания) и дублировать
   его нельзя.** Расширять только новыми источниками.

## Команды

```bash
make            # список команд
make doctor     # починить torch, если он стал CPU-сборкой
make preflight  # проверка GPU и оценка VRAM
make fetch      # скачать корпус проактивности
make data       # собрать обучающий корпус
make sft        # обучить адаптер
make test       # тесты
```

## Особенности этого сервера

- **RTX 5080 Laptop, 16 ГБ, Blackwell (sm_120).** Нужен torch, собранный под
  CUDA 12.8+. Обучение только в 4 битах (QLoRA), батч 1 при накоплении 16.
- **Unsloth ограничивает версию torch сверху.** Установка или обновление любого
  пакета может понизить torch и подменить CUDA-сборку на CPU — молча, с виду
  успешно. После любой возни с зависимостями: `make doctor`.
- **Кеш Hugging Face** указан на внешний диск, который бывает недоступен на
  запись. Проект сам перенаправит его и напишет об этом.
- **Места на диске мало.** Базовая модель — предквантованный
  `unsloth/Qwen3-8B-unsloth-bnb-4bit` (7 ГБ вместо 15.3 ГБ у `Qwen/Qwen3-8B`).
- **`Salesforce/xlam-function-calling-60k` закрыт авторизацией.** Не добавляйте
  его без `HF_TOKEN`; в конфиге используются открытые аналоги.

## Как здесь работают

- Тесты обязаны проходить: `make test`. На каждую починку — тест, который
  падал бы до неё.
- Комментарии объясняют **почему**, а не что. Формулировки на русском.
- Не подгоняйте тест под код, если тест поймал реальную проблему: сначала
  разберитесь, кто прав.
- Числа в отчётах — только измеренные. Если что-то не проверено, так и пишите.
